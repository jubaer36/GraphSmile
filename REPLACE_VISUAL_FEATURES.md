# Replacing `videoVisual` with VLM Embeddings

This document explains the purpose of `replace_visual_features.ipynb` (IEMOCAP) and
`replace_visual_features_meld.ipynb` (MELD), what they produce, and how the output
integrates seamlessly with the rest of the GraphSmile codebase.

---

## Motivation

The original PKL files store `videoVisual` as low-dimensional, hand-crafted visual
features extracted from video frames (e.g., 342-dim pose/AU descriptors for IEMOCAP,
similar sized vectors for MELD).  
These notebooks replace those features with rich, language-grounded embeddings produced
by a pre-trained Transformer — the "VLM analysis" text in the manifest CSVs is already a
detailed, utterance-level description of the speaker's facial expressions and body
language generated by a Vision–Language Model.  Encoding that text into a dense vector
gives access to much more semantic information than the raw visual descriptors while
keeping the rest of the pipeline untouched.

---

## High-Level Pipeline (both notebooks)

```
manifest CSV                     Original PKL
(utterance_id → vlm_analysis)    (videoVisual = low-dim visual descriptors)
        │                                    │
        └────────────────┬───────────────────┘
                         ▼
          Transformer encoder (batched, CLS token)
                         │
                         ▼
          new_videoVisual  (768-dim float32 per utterance)
                         │
                         ▼
              New PKL saved to disk
          (identical structure, only videoVisual replaced)
```

## Notebook 1 — `replace_visual_features.ipynb` (IEMOCAP)

### Source files
| File | Role |
|---|---|
| `Dataset/CFN-ESA/iemocap_multi_features.pkl` | Input PKL (12 fields) |
| `manifest.csv` | VLM analysis texts keyed by `utterance_id` |
| `Dataset/CFN-ESA/iemocap_vlm_visual.pkl` | **Output PKL** |

### PKL structure (12 fields, unpacked in order)
```python
videoIDs, videoSpeakers, videoLabels,
videoText0, videoText1, videoText2, videoText3,
videoAudio, videoVisual,          # ← only videoVisual is replaced
videoSentence, trainVid, testVid
```
Loaded with `encoding="latin1"` (legacy pickle requirement).

### Encoder: `allenai/longformer-base-4096`
- **Why Longformer?** The `vlm_analysis` texts are long, paragraph-length descriptions.
  Longformer handles up to 4 096 tokens with linear attention, so no text is truncated.
- CLS token (position 0) receives **global attention**; all other positions use local
  sliding-window attention.
- The CLS hidden state (`last_hidden_state[:, 0, :]`) is taken as the utterance embedding.
- Output dimension: **768** (`hidden_size` of `longformer-base-4096`).

### Steps
1. **Load** — original PKL + `manifest.csv` → build `utterance_id → vlm_analysis` dict.
2. **Coverage check** — verify every PKL utterance has a manifest entry; missing ones
   fall back to an empty string (zero vector after encoding).
3. **Load Longformer** — tokenizer + model moved to GPU if available.
4. **Encode** — all utterances in batches of 8; no truncation; global attention on CLS.
5. **Rebuild `videoVisual`** — iterate `flat_records` and slot each 768-dim vector back
   into its `(dialogue, utterance_index)` position.
6. **Save** — 12-field list pickled to `iemocap_vlm_visual.pkl` (protocol 4).
7. **Verify** — reload from disk; assert 151 dialogues, 7 433 utterances, visual shape
   `(n_utts, 768)`, all other fields bitwise-identical to original.

## Notebook 2 — `replace_visual_features_meld.ipynb` (MELD)

### Source files
| File | Role |
|---|---|
| `Dataset/CFN-ESA/meld_multi_features.pkl` | Input PKL (14 fields) |
| `meld_vlm_manifest.csv` | VLM analysis texts with a `split` column |
| `Dataset/CFN-ESA/meld_vlm_visual.pkl` | **Output PKL** |

### PKL structure (14 fields, unpacked in order)
```python
videoIDs, videoSpeakers, videoLabels, videoSentiments,   # ← extra vs IEMOCAP
videoText0, videoText1, videoText2, videoText3,
videoAudio, videoVisual,          # ← only videoVisual is replaced
videoSentence, trainVid, testVid, _extra   # ← trailing None
```
No `encoding="latin1"` needed (newer pickle format).

### Key difference — split-aware dialogue ID mapping
MELD's PKL uses global dialogue keys (0–1431), but `meld_vlm_manifest.csv` stores
`Dialogue_ID` values that **restart from 0** within each split.  
The `get_vlm_text()` function handles this with pre-computed offsets:

| Global PKL key range | Split | Manifest `Dialogue_ID` |
|---|---|---|
| 0 – 1038 | train | `global_key` (no offset) |
| 1039 – 1152 | dev | `global_key − 1039` |
| 1153 – 1431 | test | `global_key − 1153` |

### Encoder: `bert-base-uncased`
- BERT max context is 512 tokens; texts are truncated if longer (flagged in the stats
  cell).
- CLS embedding (`last_hidden_state[:, 0, :]`) is used.
- Empty-string placeholders (missing entries) encode a `"."` but the embedding is then
  zeroed out explicitly.
- Output dimension: **768** (`hidden_size` of `bert-base-uncased`).

### Steps
1. **Load** — PKL + `meld_vlm_manifest.csv` → three per-split lookup dicts
   (`vlm_train`, `vlm_dev`, `vlm_test`).
2. **Coverage check** — call `get_vlm_text()` for every utterance; report missing.
3. **Load BERT** — tokenizer + `BertModel` on GPU.
4. **Encode** — batched, truncated at 512; zero vectors for missing entries.
5. **Rebuild `videoVisual`** — same slot-back logic as IEMOCAP notebook.
6. **Save** — 14-field list, float32, `meld_vlm_visual.pkl` (protocol 4).
7. **Verify** — reload; assert 1 432 dialogues, 13 708 utterances, shape
   `(n_utts, 768)`, float32 dtype, all other fields unchanged including `videoSentiments`.

## Seamless Integration with the Codebase

The notebooks were designed so that **no other file needs to be modified** beyond
updating the PKL path and the visual `embedding_dim`.

### 1 — PKL structure is preserved

`IEMOCAPDataset_BERT` and `MELDDataset_BERT` in `dataloader.py` unpack the PKL tuple
positionally:

```python
# IEMOCAPDataset_BERT.__init__  (dataloader.py)
(
    self.videoIDs, self.videoSpeakers, self.videoLabels,
    self.videoText0, ..., self.videoText3,
    self.videoAudio, self.videoVisual,   # ← reads position 8
    self.videoSentence, self.trainVid, self.testVid,
) = pickle.load(open(path, "rb"), encoding="latin1")
```

Because the notebooks preserve the field count and position order (only swapping the
`videoVisual` arrays), the Dataset classes load the new PKL unchanged.

### 2 — Dataset `__getitem__` is dimension-agnostic

```python
# from IEMOCAPDataset_BERT.__getitem__  (dataloader.py)
torch.FloatTensor(np.array(self.videoVisual[vid]))
```

`FloatTensor` wraps whatever shape array it receives, so switching from 342-dim to
768-dim requires zero changes here.

### 3 — Model accepts any visual input size via `embedding_dims`

`GraphSmile.__init__` in `model.py` builds a projection layer driven by
`embedding_dims[1]`:

```python
# model.py
self.dim_layer_v = nn.Sequential(
    nn.Linear(embedding_dims[1], args.hidden_dim),  # ← reads the dim at runtime
    nn.LeakyReLU(),
    nn.Dropout(args.drop),
)
```

This linear layer projects the visual features (whatever dimension) into the shared
`hidden_dim` space.  Changing the visual source only requires telling the model the
new `embedding_dims[1]` value.

### 4 — `run.py` wires everything together

`run.py` is the only file that needed updating, and it already reflects the new values:

```python
# run.py
MELD_path    = 'Dataset/CFN-ESA/meld_vlm_visual.pkl'      # new pkl
IEMOCAP_path = 'Dataset/CFN-ESA/iemocap_vlm_visual.pkl'   # new pkl

if args.dataset == 'IEMOCAP':
    embedding_dims = [1024, 1024, 1582]   # [text, visual(768→proj), audio]
elif args.dataset == 'MELD':
    embedding_dims = [1024, 768, 300]     # visual = 768 (BERT-base VLM)
```

`embedding_dims[1]` is passed straight to `GraphSmile`, which constructs `dim_layer_v`
accordingly.  All training, validation, and inference code paths remain unmodified.

## Summary of Changes Per Dataset

| Property | IEMOCAP (original) | IEMOCAP (VLM) | MELD (original) | MELD (VLM) |
|---|---|---|---|---|
| PKL file | `iemocap_multi_features.pkl` | `iemocap_vlm_visual.pkl` | `meld_multi_features.pkl` | `meld_vlm_visual.pkl` |
| PKL fields | 12 | 12 (unchanged) | 14 | 14 (unchanged) |
| Visual dim | 342 | 768 | ~342 | 768 |
| Visual dtype | float32 | float32 | float64 | float32 |
| Visual source | hand-crafted AUs/pose | Longformer CLS (vlm_analysis) | hand-crafted | BERT-base CLS (vlm_analysis) |
| Encoder | — | `longformer-base-4096` | — | `bert-base-uncased` |
| Truncation | — | None (≤4096 tokens) | — | 512 tokens |
| Dialogues | 151 | 151 | 1432 | 1432 |
| Utterances | 7433 | 7433 | 13708 | 13708 |
